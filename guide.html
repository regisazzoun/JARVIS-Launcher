GRATUIT · OUTILS NATIFS · AUCUN SERVEUR LOCAL

Votre Mac, prêt à lancer JARVIS.

Le site génère uniquement des demandes identifiées. L’application locale ouvre Terminal après contrôle du matériel, du profil et confirmation. Aucune clé, aucun mot de passe et aucune commande libre ne transitent dans les URL.

1. Récupérer les sources

Après publication du dépôt dédié, téléchargez ses sources depuis GitHub ou clonez-le :

git clone https://github.com/regisazzoun/JARVIS-Launcher.git
cd JARVIS-Launcher
git switch codex/jl-01-jarvis-launcher

Si le dépôt n’est pas encore créé, utilisez l’archive de livraison fournie dans le rapport JL-01. Le launcher reste indépendant du dépôt principal.

2. Installer sur chaque Mac

Vérifiez d’abord que votre clé SSH existante se trouve à ~/.ssh/id_ed25519_jarvis. Ne copiez jamais une clé privée dans ce dépôt. Installez Tailscale et connectez-vous au réseau habituel si nécessaire.

# Sur le MacBook Pro uniquement
bash macos/install.sh macbook-pro

# Sur le Mac mini client uniquement
bash macos/install.sh mac-mini

Le matériel est vérifié. Un profil incompatible bloque l’installation. L’application est créée dans ~/Applications/JARVIS Launcher.app. Elle est signée localement sans abonnement ; elle n’est pas notariée par Apple. Aucun sudo requis, aucun script JARVIS distant dupliqué.

3. Autoriser et vérifier

Autorisez le navigateur à ouvrir JARVIS Launcher. Lors de la première action, macOS peut demander l’autorisation de contrôler Terminal : acceptez pour le lanceur ou osascript. Dans Réglages Système → Confidentialité et sécurité → Automatisation, réactivez Terminal si vous avez refusé. Aucun accès complet au disque ou permission Accessibilité requis par cette implémentation.

Le bouton « Vérifier sur ce Mac » affiche un diagnostic local. Il ne mesure pas SSH ou Tailscale et ne transmet aucun état au site. Le navigateur ne peut pas déterminer sûrement si l’application est installée.

4. Travailler avec JARVIS

Choisissez le poste sur lequel vous travaillez, puis l’action. Le serveur reste le même. « Codex sous tmux » reprend exactement la session choisie ou en crée une ; « Retrouver une session » ne la crée pas. Pour quitter tmux sans arrêter Codex : Ctrl+B, puis D. « Ouvrir mon espace » propose trois fenêtres après confirmation.

Le tunnel écoute uniquement sur 127.0.0.1. Gardez son Terminal ouvert, puis ouvrez le lien JARVIS Web. Pour l’arrêter, utilisez Ctrl+C. Sur mobile, les commandes sont proposées à copier sur le Mac correspondant.

Configurer

Le fichier site/config.json configure les profils, favoris, sections, libellés et sessions. Les actions restent limitées aux IDs reconnus. Sur chaque Mac, la configuration réellement utilisée est ~/Library/Application Support/JARVIS Launcher/config.json. Modifier le site ne modifie pas silencieusement ce fichier : mettez à jour séparément ses paramètres si nécessaire. Le profil installé doit rester celui du matériel réel.

Dépannage

  • Lanceur absent : utilisez « Copier », ou réinstallez puis autorisez l’ouverture du protocole.
  • SSH échoue : vérifiez la clé, Tailscale et JARVIS ; choisissez explicitement « SSH JARVIS · LAN » seulement sur le bon réseau.
  • Nouvelle clé d’hôte : comparez son empreinte avec une source de confiance. Ne désactivez pas ce contrôle.
  • Codex ou tmux absent : un message apparaît et le shell distant reste ouvert. Aucune installation automatique.
  • Session tmux absente : l’attachement affiche un message ; aucune suppression ou fusion.
  • Port 8765 occupé : changez localWebPort dans le profil local et dans le site, par exemple 8766. Le port distant reste 8765.
  • Copie refusée : utilisez la sélection du texte et ⌘C. Le presse-papiers automatique exige notamment un contexte sécurisé.
  • Matériel non reconnu : action bloquée ; joignez le nom matériel du Mac à un ticket, sans identifiants ni numéro de série.

Sécurité

La liste blanche et la configuration locale sont l’autorité. Les URL acceptent un profil, un ID d’action et, pour tmux, un nom de session autorisé. Toute URL malformée, commande libre, argument supplémentaire ou session non autorisée est rejetée. N’importe quel site peut demander une action connue : la confirmation locale est obligatoire. Ne confirmez que vos propres clics. Une session Codex interactive conserve ses propres capacités ; le lanceur n’en limite pas les futures commandes.

Désinstaller

bash macos/uninstall.sh

L’application est déplacée dans la Corbeille après confirmation. Les clés SSH, configurations, anciens scripts, sessions tmux et sauvegardes sont conservés.

État de validation

Les tests du navigateur et de la politique peuvent être exécutés sur Linux. L’installation, l’enregistrement du protocole et Terminal.app nécessitent une réception réelle sur chacun des deux Macs. Ne considérez pas cette réception comme acquise sans le rapport correspondant.
